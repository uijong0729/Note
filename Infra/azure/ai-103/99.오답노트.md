# 1. モデルとプロンプト
### 1-1. 温度
- 温度を下げると、応答のランダム性が減り、同じ入力に対する出力の再現性・一貫性が高まります。
- 出力の一貫性を下げたり上げたりするために、最初に調整すべきモデル パラメーター

### 1-2. ペナルティ
- 頻度ペナルティ: 同一トークンの繰り返しを抑える調整
- 存在ペナルティ: 新しい話題の出現を促す調整

### 1-3. マルチパートユーザーメッセージ
- テキストと画像を1つのユーザーメッセージにまとめて送信できる形式

# 2. ドキュメント理解
### 2-1. Azure Content Understanding
- プロジェクト作成の GUI ツール
- ドキュメント理解・コンテンツ理解を支援する統合ツール
- 標準モード：単一ファイル
- Proモード：複数ファイルの同時処理と多段推論

### 2-2. スキルセット（skillset）
- AIスキルによる「エンリッチ処理」の手順を定義するリソース
    - エンリッチ処理 : 데이터나 문서에서 의미있는 정보를 추출해 데이터를 강화하는 과정
- OCR（Optical Character Recognition）やエンティティ抽出などの強化ステップをまとめる

### 2-3. Work IQ
- Microsoft 365 のコンテキスト インテリジェンス層
- 組織の働き方の文脈をエージェントに提供する

# 3. Azure AI Search
### 3-1. Azure AI Search
- リソースの役割の区別
    - スキルセット : AIエンリッチ処理の手順定義、
    - データソース : 取り込み元、
    - インデクサー : 両者を結ぶ実行単位
- シノニムマップ（Synonym Map）
    - 異なる語句や表現が同じ意味を持つことを定義するリソース
- セマンティック検索
    - 検索クエリの意味を理解して、より関連性の高い検索結果を返す検索機能
- ベクター検索
    - 検索クエリをベクトルに変換し、ベクトル空間上で類似度の高いドキュメントを検索する機能

### 3-2. 埋め込みモデル（embedding model）
- テキストをベクトルに変換するモデル

# 4. 画像とマルチモーダル
### 4-1. キャプション生成
- 画像に対して、簡潔な説明や詳細な説明を生成する機能

### 4-2. 画像分類
- 画像全体に対して 1 つのラベルを割り当てるモデル
- 画像ごとに単一の分類結果を返す本要件に適する

# 5. AI Foundry と Agent
### 5-1. Foundry Tools
##### 5-1-1. Rest API
- Ocp-Apim-Subscription-Key：リクエストにキーを付与するために使用するHTTPヘッダー
##### 5-1-2. 評価機能
- 評価には、入力と評価基準を含むテストデータセットを先ず用意する必要がある。
- 関連性(relevance)・根拠性(groundedness)などの評価メトリックを選び、データセットに対して評価を実行することで、応答品質を体系的に測定できる。
- モデルのドリフト(drift：漂流)
    - ユーザーが入力する内容の傾向が時間とともに変わることで、デプロイ当初より応答の精度や関連性が落ちていく現象

### 5-2. AI Agent
- 操作の事後追跡・規制対応
    - トレース ログと実績メタデータ、および承認ワークフローを用いた監査により、エージェントの各操作の時刻・内容・根拠を後から追跡できます
- OpenAPI 仕様ツール 
    - OpenAPI定義を持つWebサービスの呼び出し
- tool capability(ツール機能)の種類
    - web_search : Web検索
    - code_interpreter : Pythonコードの実行
    - file_search : アップロード文書からの回答用ツール
- オーケストレーションパターン
    - 複数のエージェントやサービスを調整し、連携させる方法や設計のパターン
    - **引き渡し(Responsibility Handover)**
        - 最初に応対した一次受けエージェントが、問い合わせ内容に応じて、状況の変化に合わせて適切な専門エージェントへ責任そのものを動的に移譲（いじょう）するパターン
    - **逐次（Sequential）**
        - エージェントを事前に定義した順序で順番に実行するパターン
    - **コンカレント（Concurrent）**
        - 複数のエージェントを並列に実行し、結果を統合するパターン
    - **グループチャット（Group Chat）or Collaboration**
        - 複数のエージェントが同じタスクを協力して行うパターン
- Microsoft 365 Agents Toolkit
    - カスタムSSO・カスタムミドルウェア・複数環境へのデプロイなど、Teams向けエージェントの高度なカスタマイズと環境管理に使う

# 6. 認証とセキュリティ
### 6-1. マネージド ID
- Microsoft Entra ID が発行・管理する ID で、シークレットをコードに保存せずトークンベースでリソースにアクセスでき、キーのローテーション運用も不要

### 6-2. Shared Access Signature
- 有効期限付きトークン文字列を発行する仕組みで、依然として資格情報の生成・配布・更新が必要

# 7. AI エージェントの開発
### 7-1. Python SDK
- AIProjectClient 
    - PythonアプリからFoundryプロジェクトへ接続し、ネイティブなプロジェクト操作を行うために使用するクライアントクラス
        `from azure.ai.projects import AIProjectClient`
    - get_openai_client()
        - AIProjectClient から OpenAI 互換クライアントを取得するメソッド

### 7-2. OpenAI API
- responses.create()
    - OpenAI 互換クライアントを取得してから実行
    - Responsesを用いて応答を生成する際に呼び出すメソッド
- モデル推論 API
    - デプロイ済みモデルにプロンプトを送り、応答のストリーミングや関数呼び出しを統合するためにアプリコードから直接呼び出すインターフェイス

### AI評価
##### 評価メトリック
- 関連性 : モデルの応答が、利用者の質問の意図にどれだけ的確に対応できているかを測りたい場合、用いるべき評価メトリック
### デプロイオプション
- 標準デプロイ
    - 容量予約が不要で、処理したトークン量に応じた従量課金
    - トラフィック・リージョン分散を必要としないシナリオに合致
- プロビジョニング済みスループットデプロイ(Provisioned Throughput Deployment)
    - 定額で、容量を事前予約する方式
    - Provisioned Throughput : 準備された処理量
- バッチデプロイ
    - 大量リクエストを非同期でまとめて処理する方式
    - 対話型のリアルタイム利用はできない

### 8-1. 情報抽出
- Content Understanding：analyzeを呼び出し（すぐに解析結果を返さず）、結果を取得するにはOperation-Locationをポーリング(polling)して取得

- キーワード（全文）検索とベクター（意味的）検索を組み合わせ、両方の長所を活かして文書を取得
- キーワードの一致だけでなく、語句の意味的な近さでも文書を取得する検索方法
